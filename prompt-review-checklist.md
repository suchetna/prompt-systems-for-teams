# Prompt Review Checklist

Use this checklist before a prompt (or prompt set) is shared with a team.

## 1. Purpose

- Is the outcome of this prompt clear?
- Is it tied to a real task in the workflow?
- Is there an example of a “good” output?

## 2. Inputs

- Does the prompt ask for the right inputs?
- Are placeholders clearly marked (e.g., {{brief}}, {{data}})?
- Are there any hidden assumptions about context or data?

## 3. Instructions

- Is the instruction written in plain language?
- Does it specify audience, tone, and format?
- Does it set limits (what to avoid, where to stop)?

## 4. Structure

- Is the prompt broken into clear sections (context, task, constraints, examples)?
- Are bullet points used for multi-step instructions?
- Is the requested output structure explicit (lists, tables, headings)?

## 5. Constraints and guardrails

- Does the prompt remind the model to avoid making up facts?
- Does it say what to do when information is missing or uncertain?
- Does it ask for sources or reasoning when appropriate?

## 6. Review and testing

- Has the prompt been tested with 3–5 varied examples?
- Has someone else on the team reviewed the outputs?
- Are failure modes or weird outputs documented?

## 7. Reuse

- Is the prompt named in a way that makes sense to others?
- Is there a short description of where in the workflow it fits?
- Is the latest “good” version saved where the team can find it?
